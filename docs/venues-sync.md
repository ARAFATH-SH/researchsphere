# Automatic venue import (FR-14.5)

Venues come from three open sources, once a day and when an administrator asks. This
replaces nothing: an administrator still adds a venue by hand (`POST /admin/venues`) or in
bulk from a file (`docs/venues-import.md`), for example a local Bangladeshi event that no
source lists. SRS 8.2 was decided on 24 November 2026; the licences and the rules below are in
`docs/decisions.md` (2026-11-24).

## Sources

| Source (`source`) | What | Read from | Licence |
| --- | --- | --- | --- |
| `ccfddl` | Conference editions in computer science, by CCF area | https://github.com/ccfddl/ccf-deadlines, branch `main`, `conference/<area>/*.yml` | MIT |
| `hci_deadlines` | Conference editions in human-computer interaction | https://github.com/hci-deadlines/conf-database, branch `main`, `conferences/*.yml` | MIT |
| `openalex` | Journals, which take submissions at any time (rolling) | https://api.openalex.org/sources | CC0 |

Not used: sec-deadlines (no licence), huggingface/ai-deadlines (generated by AI agents from
ccf-deadlines' AI folder, so duplicates), WikiCFP and every site without an API (never
scraped). No maintained, licensed repository of healthcare deadlines was found.

## When it runs

- **Daily**, when `VENUE_SYNC_DAILY=true`: every hour the API checks whether a source's last
  scheduled run started 20 hours ago or more, and runs the sources one after another
  (`ccfddl` first). Several API instances share a row per source in `venue_sync_sources`, so
  each source runs once between them.
- **On demand**: `POST /api/v1/admin/venues/sync` (optional body `{"sources": [...]}`), with
  `?dryRun=true` to report without writing. It answers 202 at once; `GET
  /api/v1/admin/venues/sync` shows each source's last real and dry run. A real run of a
  source is refused (429 `venue_sync_too_soon`) less than `VENUE_SYNC_MIN_INTERVAL` (1 hour)
  after the last one; a dry run is not. A run in progress refuses another (409
  `venue_sync_running`).
- **By hand**: `make venue-sync [dry=1] [sources=ccfddl,openalex]` runs at once and prints the
  counts.

Nothing runs without `VENUE_SYNC_CONTACT_EMAIL` (503 `venue_sync_unconfigured`).

## Politeness

- Every request sends `User-Agent: ResearchSphere/1.0 (+https://github.com/ARAFATH-SH/researchsphere; mailto:<VENUE_SYNC_CONTACT_EMAIL>)`.
- At most 4 requests a second per source, 15 seconds per request, 20 minutes per run.
- A timeout, a dropped connection, 429 or a 5xx is tried again 3 times, after 1, 4 and 16
  seconds (plus up to a quarter at random), or after the `Retry-After` the answer gives (at
  most a minute). Any other error status is not retried.
- GitHub allows 60 API calls an hour per address without a token. A used-up limit (403 or 429
  with `X-RateLimit-Remaining: 0`) is not retried: the run fails with the reset time, and the
  next day's run goes on from the stored commit.
- At most 4 MiB per API answer and 1 MiB per data file; more is an error, never truncated.
- **Repositories**: the branch head is asked for with `If-None-Match` and the ETag of the last
  run; GitHub answers 304 when nothing moved, which costs nothing, and the stored files are
  used. A new commit is compared with the last one (`/compare/<old>...<new>`) and only the
  changed data files are read, at that commit from `raw.githubusercontent.com`. The first
  run, a rewritten history or a change of 300 files or more lists the tree once and reads
  every data file (ccf-deadlines: about 390 files, 750 KB). At most 3 API calls per run.
- **OpenAlex** sends no ETag, so each run reads the filtered list in full: pages of 100,
  sorted by works count, a few dozen requests (OpenAlex's `page` paging, which needs no key
  up to 10,000 results). `mailto` is sent as asked, though OpenAlex no longer documents a
  "polite pool"; `OPENALEX_API_KEY` (free) raises the daily budget and is never logged.
- **Homepages**: see Journals.

## What is imported

Each entry becomes a venue checked with the rules of `VenueInput` (the same as an
administrator's), keyed by `source` + `source_key`. A rejected entry is skipped with every
reason; the others are still written.

| Entry | Outcome |
| --- | --- |
| No venue of this source has the key | **created** |
| The venue exists and a value differs | **updated** in place, the changed fields named in the audit row |
| The venue exists and nothing differs | **unchanged** |
| The venue was removed, or an administrator edited it (`locked`) | **skipped**, never changed or brought back |
| A `hci_deadlines` edition that `ccfddl` also lists (same short name and year) | **skipped** |
| A rule is broken | **rejected**, with `{field, code}` reasons (at most 200 kept per run) |

A venue added by hand (`manual`) or by a file (`import`) is never matched: its source differs.
Every write has an audit row in `venue_actions` with `actor = import`, no user, the name
`Automatic import`, `import_create` or `import_update`, and the run's ID as `import_id`. The
embedding triggers (AI-1.3) queue each new or changed venue, at low priority (1, like
`make embed-backfill`), so a first run does not hold up users' own changes.

A **dry run** reads the sources, checks every entry and counts the same outcomes, then
rolls the writes back; it stores nothing it read (no commit, ETag, file or link check), only
its run. Because it stores no files, a dry run of `hci_deadlines` before `ccfddl`'s first real run
cannot skip the editions ccf-deadlines also lists, and counts them as created.

**Locked**: when an administrator changes a synced venue (`PATCH /admin/venues/{id}`), it is
locked (`locked: true` on the venue) and the sync leaves it alone from then on. There is no
unlock yet; removing it and letting the sync create it again is not possible either (a
removed key is never brought back).

### Conferences

| Field | From |
| --- | --- |
| `source_key` | `ccfddl:<id>` or `hci_deadlines:<id>`, the edition's own ID such as `sigmod27`. Each edition is its own venue; past editions stay. |
| name, short name | The full name (`description`, `full_name`), else the short name; the short name (`title`) when it differs and fits 40 characters |
| type | `conference` |
| deadline | The next round whose deadline has not passed, else the last round; its abstract deadline. `TBD` rounds are ignored; an edition with only TBD rounds is rejected (`deadline_tbd`) unless its year is two or more years past. |
| time zone | See below |
| attendance, city, country | See Places |
| event dates | `start`, `end` (hci-deadlines only) |
| link | As given; `http://` is rejected (`not_https`) |
| fields | Area table below |
| scope | Generated: the full name and year, the area, the ranks (CCF, CORE, THCPL), the number of rounds, and "Imported from …" |

An edition whose chosen deadline closed more than **90 days** ago is not read at all (it is
neither changed nor deleted).

**Time zones**, as the repositories write them:

| Source | Ours |
| --- | --- |
| `AoE`, `UTC-12`, `GMT-12`, empty (the repositories' own default) | `AoE` |
| `UTC`, `UTC+0`, `GMT` | `UTC` |
| `UTC+N`, `UTC-N` (whole hours) | `Etc/GMT-N`, `Etc/GMT+N` (IANA inverts the sign) |
| `PT`, `PST`, `PDT` | `America/Los_Angeles` |
| `ET`, `EST`, `EDT` | `America/New_York` |
| An IANA name such as `Asia/Seoul` | As is |
| Anything else, such as `UTC+5:30` | rejected (`invalid_time_zone`) |

A deadline `2027-01-04 23:59:59` in `UTC-12` is stored as 2027-01-05 11:59:59 UTC with the
label `AoE`.

**Places**: `Online` or `Virtual` is online. `(Hybrid)`, `/ Online`, `& Virtual` or `and
Online` make it hybrid. Otherwise in person. The country is the last part after a comma,
looked up by name (ISO 3166-1 names and the repositories' aliases: USA, UK, England,
Scotland, Korea, Türkiye, Hong Kong SAR and others; `countries.go`); a US state or its code
as the last part means the US (`San Diego, CA`); a place starting with a country name is that
country (`Singapore EXPO`). The city is the part before the country, skipping a state or
region (`Los Angeles, CA, USA`, `Aberdeen, Scotland, UK`). An unknown country is rejected
(`unknown_country`).

### Journals

OpenAlex is asked for core journals still publishing, with more than
`VENUE_SYNC_OPENALEX_MIN_WORKS` (5,000) works, that have a topic in one of the subfields
below: `type:journal,is_core:true,works_count:>5000,last_publication_year:><year − 2>,topics.subfield.id:<list>`.
Of those, a journal is imported only when its **main** (first) topic is in a listed subfield,
so a general journal with one AI topic among many is left out. Its fields come from its top 3
topics. The live dry run of 24 November 2026 kept 834 journals (833 created, 1 rejected).

That dry run, on an empty database: ccfddl at `193d48d5` 190 created, 41 rejected (37
`deadline_tbd`, 3 `not_https`, 1 `unknown_country`); hci_deadlines at `e6af4d6d` 12 created
(duplicates of ccf not yet skipped, see the dry run note); openalex 833 created, 1 rejected.

| Field | From |
| --- | --- |
| `source_key` | `openalex:<id>`, such as `openalex:S196734849` |
| name | `display_name` |
| type | `journal`, **rolling**: no deadline, no time zone |
| link | See below |
| scope | Generated: main topics (up to 5), publisher, ISSN-L, "Imported from OpenAlex." |

**The link** (docs/decisions.md, 2026-11-24): the homepage, with `http://` rewritten to
`https://`, is checked with a HEAD request (a GET when HEAD gets 405 or 501): 5 seconds, at
most 5 redirects that must all stay https, never to a private, loopback, link-local or
carrier-grade NAT address (checked on the address dialled). It **answers** when the final
status is below 500 and not 404, 410 or a redirect: many publishers answer 403 to anything
but a browser, and the page is still there for a person. A check is kept in
`venue_sync_link_checks` and made again after 30 days; 8 run at a time. When the homepage
does not answer or there is none, the link is `https://portal.issn.org/resource/ISSN/<issn_l>`
and the venue's `linkKind` is `issn_portal`, so an administrator can set the real one (which
makes it `official` and locks the venue). With neither, the journal is rejected (`required`).

## Reasons a run rejects an entry

The codes of `VenueImportReason`, plus:

| Code | Meaning |
| --- | --- |
| `deadline_tbd` | Every round's deadline is TBD |
| `unknown_country` | The place's country is not one the table knows |

A data file that is not YAML of the expected shape is listed in the run's `errors` and its
editions are skipped; the other files are still read. A source that cannot be read at all
fails the run (`status: failed`, with the message); the other sources still run.

## State

| Table | Holds |
| --- | --- |
| `venue_sync_sources` | Per source: the commit and ETag last read, the lease of the run in progress, when the last scheduled and real runs started |
| `venue_sync_files` | The data files at the commit last read |
| `venue_sync_runs` | Each run (the last 30 per source): trigger, status, counts, errors, rejects |
| `venue_sync_link_checks` | Each journal homepage checked, with its result and time |

A run cut off by a restart is marked failed ("The run was interrupted.") when the next run
of its source starts after its lease (the run's 20 minutes plus 5).
