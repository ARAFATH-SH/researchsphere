# Decisions

One entry per decision: the date, what was decided and why. Add to the end; do not rewrite
old entries. To change a decision, add a new entry that replaces the old one.

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-10-05 | The API server is one Go application divided into modules (a modular monolith). Only the sync, compile and AI services are separate. | One developer; fewer moving parts to deploy and debug. A module can become its own service later. |
| 2026-10-05 | Embeddings are stored in PostgreSQL with pgvector, not in a separate vector database. | One database to run and back up; enough for 10,000 profiles (NFR-1). |
| 2026-10-07 | Requirements live in `docs/SRS.md`, and every slice names the requirement IDs it covers. | Keeps code traceable to requirements. |
| 2026-10-07 | The local PostgreSQL container listens on port 5433. | Port 5432 may already be used by a PostgreSQL installed on Ubuntu. |
| 2026-10-08 | Top-level folders are `frontend/`, `backend/`, `ai/`, `sync/`, `compile/` and `docs/`. | Each service is easy to find, and each can be built and deployed on its own. |
| 2026-10-08 | Project instructions for AI assistants are in `AGENTS.md`. The repository has no `CLAUDE.md`. | Claude Code reads `AGENTS.md` when no `CLAUDE.md` exists; one file avoids two sets of rules. |
| 2026-10-08 | CI is one GitHub Actions workflow, `.github/workflows/ci.yml`. A `detect` job runs the backend, frontend and ai jobs only when `go.mod`, `package.json` or `pyproject.toml` exists, and fails when a folder has source files but no manifest. | Jobs stay green before any code exists, and a missing manifest cannot make real code skip its checks. |
| 2026-10-08 | CI uses golangci-lint v2.14.0. Actions are pinned to a major version, except `astral-sh/setup-uv`, which is pinned to an exact release because it publishes no major tags. | Same linter version as on the developer's machine; major pins get fixes without surprise breaking changes. |
| 2026-10-09 | Embeddings are `vector(768)`. A model with another output size needs a new migration and a full re-embed. | 768 fits SPECTER2 and all-mpnet-base-v2, so either can be chosen in the AI-1 slice; HNSW indexes need a fixed size. |
| 2026-10-09 | Sessions (refresh tokens) and one-time tokens (verification, reset) are PostgreSQL tables, added to SRS section 7. Login lockout (FR-2.7) and rate limits (NFR-8.3) are Redis counters, not tables. | Sessions must survive a Redis restart (30-day tokens); counters are short-lived and expire on their own. |
| 2026-10-09 | "Exactly one owner per project" is enforced in the database: a partial unique index allows at most one, and a deferred constraint trigger requires one at commit. | The SRS requires the rule in the database. Deferring the check lets a project and its owner, or an ownership transfer, be written in one transaction. |
| 2026-10-09 | Down migrations remove everything their up file created, extensions included. CI applies all migrations, undoes them, checks that the public schema is empty, and applies them again. CI installs golang-migrate v4.18.3 and checks its sha256. | NFR-11.1 requires migrations that can be undone; the check catches a down file that misses something. |
| 2026-10-09 | The API server uses the standard library `net/http` server and `ServeMux`, with no web framework. Routes and types are generated from `docs/openapi.yaml` by oapi-codegen (`std-http-server` and `strict-server`), and handlers implement the generated strict interface. | Go 1.22 routing patterns are enough; the strict interface lets a handler return only responses the contract declares. |
| 2026-10-09 | Generated code (`backend/internal/api/api.gen.go`) is committed. CI regenerates it and fails when it differs. oapi-codegen is pinned with a `tool` directive in `backend/go.mod` and run with `go tool`. | Code review shows the generated changes; one pinned generator version gives the same output locally and in CI. |
| 2026-10-09 | The backend uses `jackc/pgx/v5` (pgxpool) for PostgreSQL and `redis/go-redis/v9` for Redis. `backend/go.mod` says `go 1.26`, because go-redis v9.23 requires it. | pgx/v5 is the driver sqlc generates for; go-redis serves the Redis counters (lockout, rate limits). |
| 2026-10-09 | The CI stack job runs only the database tests (`make test-db`). Go lint, tests and the generated-code check run in the backend job. | Go checks need no database; running them in one job avoids running them twice. |
| 2026-10-09 | Every error, including unknown routes (404), wrong methods (405) and recovered panics (500), uses the shape `{"code", "message"}`. The server makes a new request ID for every request, returns it in `X-Request-ID`, and ignores one sent by the client. | SRS 5.3 requires one error shape; an ID chosen by the client could forge log lines. |
| 2026-10-09 | Inside the modular monolith, each backend module follows clean architecture: `domain` (entities and interfaces, standard library only), `usecase` (business logic, imports only its own domain) and `adapter/http`, `adapter/postgres`, `adapter/redis`. Shared code is in `internal/platform`, generated code in `internal/api/gen`, and only `cmd/api` wires them together. golangci-lint's depguard enforces the dependency rule, with one `usecase-<module>` rule per module. Layers are created only when they have code. The health check is the reference module. | Business logic stays testable with fakes and free of HTTP and database details; a lint rule keeps the layering from eroding as one developer adds 30 slices. |
| 2026-10-09 | The web client is Next.js 16 (App Router) with TypeScript strict mode, Tailwind CSS 4 and ESLint, installed with npm. Node.js 22 is pinned in `frontend/.nvmrc`, and CI reads its version from that file. | One Node version locally and in CI; `create-next-app` defaults keep the setup standard. |
| 2026-10-09 | TypeScript types for the API are generated from `docs/openapi.yaml` by openapi-typescript into `frontend/src/lib/api/schema.gen.ts`, which is committed. All calls go through one openapi-fetch client in `frontend/src/lib/api/client.ts`. `make generate` regenerates the Go code and these types; CI fails when either is out of date. | The client and server are typed from the same contract (SRS 5.3); openapi-fetch is a small runtime that types paths, parameters and responses from the generated file. |
| 2026-10-09 | The browser calls `/api/v1` on the web client's origin, and a Next.js rewrite forwards it to `API_URL` (default `http://localhost:8080`). The API server needs no CORS. | No cross-origin requests; the API address stays on the server. Rewrites are fixed at `next build`, so a production build needs `API_URL` set; hosting is still open (SRS 8.2). |
| 2026-10-09 | Frontend tests use Jest with `next/jest` (SWC) and React Testing Library, in jsdom. The config is `jest.config.mjs`, not `.ts`, so that Jest needs no `ts-node`. | Jest is the runner named in the proposal; `next/jest` needs no Babel setup. |
